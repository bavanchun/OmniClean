# Git Workflow & Security

## Branching

- **NEVER implement code on `main`.** Create one feature branch per plan: `feature/<plan-slug>`
  (e.g. `feature/expand-linux-package-managers`).
- Branch off the latest `main`. Keep the branch scoped to its plan.

## Commits

- **At least one commit per phase.** Don't batch a whole plan into a single commit.
- Use **Conventional Commits**: `type(scope): subject`
  (`feat`, `fix`, `test`, `refactor`, `ci`, `build`, `docs`, `chore`).
- **No AI / assistant references** anywhere in commit messages, code comments, or PR text
  (no "Generated by", no co-author tags for assistants).
- Do not put plan IDs, phase numbers, or audit labels in commit messages — describe the behavior.

## Per phase, when done

Open a pull request and watch CI for that phase's work:

- Generic intent (any agent / harness): push the branch, open a PR against `main`, wait for CI
  (lint, test matrix, build) to pass, address failures before moving on.
- **Claude Code shortcut:** `/vchun-git prc` runs the commit → push → PR → CI-watch pipeline.
  This is a Claude-only convenience command — other harnesses (Codex, Antigravity, etc.) perform
  the equivalent steps with `git` + `gh` directly.

## Security

- Never commit secrets, dotenv files, tokens, private keys, database credentials, or personal data.
- Local agent state stays ignored (`.claude/` settings/memory, `/plans/`). Don't force-add it.
- If you spot a committed secret, stop and tell the human — do not just delete it silently.
